# 画面認識ロードマップ — 見る(Phase 1) → 速くする(Phase 2) → 手を出す(Phase 3)

2026-07-17 時点の構想。ペットが「いま画面で何が起きているか」を理解し、
将来的には指差し・カーソル操作まで行う機能の計画書。

## 前提と結論(先に要点)

- **理解は4層のピラミッドで、安い層から使う。** ピクセル(スクリーンショット)は
  最上段であって入口ではない:
  1. **ウインドウメタデータ**(`CGWindowListCopyWindowInfo`) — どのアプリがどこに。
     権限プロンプトなし。退避機能(PetEvasion)で既に実装・運用済み
  2. **Accessibility(AX)ツリー** — 前面アプリのボタン・テキスト・入力欄の**構造**。
     ピクセル不要で「何があるか」まで分かり、OCRより正確で軽い。Accessibility権限
  3. **OCR**(Vision `VNRecognizeTextRequest`) — AXが読めないアプリ(ゲーム・
     Electron の一部・画像内テキスト)の補完。画面収録権限
  4. **ローカルVLM**(Ollama のビジョン対応モデル) — 「何が起きているか」の意味理解。
     最も高価。**質問された時・依頼された時だけ**呼ぶ
- **権限は3種で、要求は段階的・明示的に**(Pome原則3・4):
  画面収録(TCC/ScreenCaptureKit)、Accessibility(AX読み取り+Phase 3の操作)、
  そして「LLMへ画面内容を渡す」ことへのアプリ内同意。既定は全てオフ。
  権限が無い層は黙って飛ばし、上位層だけで答える(フォールバック原則5)。
- **画面内容は既定でオンデバイスから出さない。** VLM/要約は localhost Ollama。
  Codex など外部処理系へ画面内容を渡すのは、既存のルーティング方針+承認カードを
  通した時だけ(会話テキストと同じ扱いに統一する)。
- **スクリーンショットは揮発**: メモリ内のみ・解析後即破棄・ディスク保存しない。
  保存はユーザーが明示操作した時だけ。**取得中インジケータ**を必ず表示する。
- **操作(Phase 3)は「見せる」と「動かす」を分ける**: 仮想カーソル(オーバーレイの
  指差し)は権限追加なしで安全に出せる。実際のマウス・キーボード操作は
  Codex承認カードと同じ「実行前個別承認」を通す。

## 非目標

- 常時録画・常時ストリーミング解析(取得はイベント/依頼駆動のみ)
- 画面内容のクラウド送信(ユーザーが明示的に外部brainを選んだ場合を除く)
- パスワード・決済画面の理解や操作の自動化(除外リストで最初から見ない)
- Phase 3 でもゲームのアンチチート回避・他者アプリの自動化ボットは作らない

## アーキテクチャ

### 新モジュール: Screen Engine(仮名。trilobite に倣い後で命名)

カメラ・マイクを `trilobite Engine` が担うのと同型に、画面感覚を1モジュールへ集約:

```
CGWindowList ─┐
AXツリー ──────┼─► Screen Engine ─► ScreenSnapshot(構造化された「今の画面」) ─► HesitateCore/会話
SCK キャプチャ ┘        │                                                    └► Pet の視線・反応
Vision OCR ────────────┘
```

- `ScreenSnapshot`: 前面アプリ、ウインドウ構成、AX由来のUI構造、OCRテキスト、
  (要求時のみ)VLM要約、を1つの構造化された値に。**取得時刻と取得層を記録**し、
  どの権限でどこまで見えたかを常に説明可能にする。
- 権限状態・インジケータ・取得はこのモジュールに閉じ、他所は `ScreenSnapshot` を
  受け取るだけ(レンダラーに判定を散らさない既存流儀)。
- 除外リスト: パスワードマネージャ・ブラウザのシークレットウインドウ・
  決済系アプリ(bundle ID + ウインドウ属性)は**取得段階で**スキップ。

### Phase 1: 理解する

| # | 内容 | 権限 | 規模 |
|---|---|---|---|
| P1-M0 | **視線の接続(即効の可愛さ)**: アクティブウインドウ/カーソル位置を `externalGazeTarget` へ — ペットが作業を目で追う。ピクセル不要 | なし | 小 |
| P1-M1 | Screen Engine 骨格: 権限管理・オンデマンド取得(SCK)・インジケータ・除外リスト・揮発性保証 | 画面収録 | 中 |
| P1-M2 | メタデータ+AX層: 前面アプリのUI構造を `ScreenSnapshot` へ。PetEvasion のウインドウ層を共用化 | AX | 中 |
| P1-M3 | OCR層: キャプチャへ Vision OCR、ウインドウ矩形と融合して「どの窓の何の文字か」に整理 | 画面収録 | 中 |
| P1-M4 | VLM層: Ollama ビジョンモデルで要約。「今なにしてるでしょう?」に会話で答える。モデル未導入時は AX+OCR だけで答える縮退経路 | 同上+同意 | 中 |
| P1-M5 | キャラ反応: 画面理解を `HesitateCore` の状態・コメントへ(頻度制限つき。退避のセリフ制限と同じ思想) | — | 小 |

**Phase 1 の受け入れ基準**
- 権限ゼロでも M0 の視線追いと「アプリ名レベル」の回答が動く(段階的縮退)
- 画面収録オフ→オンの初回フローで、何が取得され何がされないかをUIで説明する
- スクリーンショットがディスクに書かれないことをテストで保証(一時ファイル監視)
- 取得中はインジケータが必ず点灯し、取得はユーザー操作(質問・依頼)起点のみ
- 除外リストのアプリが前面のとき、取得APIが呼ばれないことを注入テストで保証

### Phase 2: 速くする

- **差分駆動**: SCStream のフレーム差分+ウインドウイベントで「変わった時だけ」解析。
  退避機能の「イベント+低頻度ポーリング」哲学の画面版
- **階層キャッシュ**: `ScreenSnapshot` を層ごとに無効化(ウインドウ移動→メタデータのみ
  更新、内容変化→OCR再実行、アプリ切替→全更新)
- **ROI**: 全画面でなくアクティブウインドウ/変化領域だけをキャプチャ・OCR
- **測定目標(仮)**: 「何してる?」応答まで AX経路 <300ms / OCR経路 <1s /
  VLM経路 <5s(モデル依存)。アイドル時の常駐コストは退避機能と同等(~0)
- 必要になったら: 小型の画面分類モデル(Arils_Dataset の流儀で自作)で
  「コード書いてる/動画見てる/会議中」程度の粗い状態を VLM なしで判定

### Phase 3: 手を出す

- **P3-M1 指差し(操作しない)**: ペットの「手」カーソルをオーバーレイ表示し、
  画面上の場所を指す・軌跡を描く。**権限追加なし・リスクなし**で
  「あそこ見て」が実現する。まずこれで体験を作る
- **P3-M2 実カーソル・実操作**: CGEvent/AX Action によるマウス移動・クリック・
  入力。**1操作ずつ Codex承認カードと同じUIで事前承認**(Pome原則4を継承)。
  ユーザーが物理マウスを動かしたら即中断(人間優先の絶対則)。操作ログを残す
- **P3-M3 操作の連なり**: 「このボタンを押して閉じておいて」級の短いシーケンス。
  計画を提示→一括承認→逐次実行+各段の検証(AXで結果確認)。失敗したら止まって報告

**Phase 3 の技術的前提(先に決める必要あり)**
- 現在のPomeは **App Sandbox 有効**。AX操作・CGEvent送出はサンドボックスと
  相性が悪く、(a)サンドボックスを外す、(b)非サンドボックスのヘルパープロセスへ
  分離、のどちらかが要る。配布方針(直接配布なら可、MAS不可)と合わせて判断
- 仮想カーソル(P3-M1)はこの制約と無関係に作れる — だから先にやる

## テスト方針

- 取得API(SCK/AX/CGWindowList)は protocol で包み、合成スナップショットを注入
  (退避機能と同じ流儀)。OCR融合・キャッシュ無効化・除外判定・縮退経路の選択は
  全て純ロジックとして `pomegranateTests` へ
- VLM は Ollama モック応答でルーティングと縮退をテスト(既存の Ollama テスト流儀)
- 「ディスク不書き込み」「除外アプリ不取得」「インジケータ点灯」は不変条件として
  専用テストを置く

## 決めておくこと(実装開始時に確認)

1. モジュール名(trilobite/Cherry/Hesitate の系譜で。仮: Periscope Engine)
2. VLMモデルの既定候補と最小要件(Ollama のビジョン対応モデルから。未導入時の
   案内文言も)
3. 除外リストの初期値(パスワードマネージャ群・シークレットウインドウ・決済系)と
   ユーザー編集UIの置き場所(Settings > Privacy?)
4. 画面内容を外部brain(Codex等)へ渡すことを許すか。許す場合の承認粒度
   (毎回/セッション/アプリ単位)
5. Phase 3 のサンドボックス方針: 本体から外すか、ヘルパー分離か
6. キャラ反応(P1-M5)の頻度・トーン: 「見られている感」が不快にならない上限
   (仮: 自発コメントは1時間に数回まで、設定でオフ可)
