# Arils 姿勢一般化ロードマップ — 「大抵の2Dイラスト」へ

2026-07-14 時点の構想。立ち絵前提を解き、浮遊・座り・寝そべり・バストアップなど
一般的なイラストの姿勢で自動リギングが成立するようにする計画書。

きっかけ: 水彩調・浮遊ポーズ・顔より大きく流れる髪の画像
(手元検証: `~/Downloads/abc.png`)で、マスクは正確に取れているのに
頭部矩形が髪全体へ肥大し、目が胸元・口が帯に誤検出された。

## 前提と結論(先に要点)

- **「姿勢を分類して姿勢別パイプラインへ振り分ける」方式は不採用。**
  理由: (1) 座り×3/4ビュー×髪量などの組み合わせ爆発でN個のメンテ地獄になる、
  (2) 誤分類した瞬間に全部壊れる「崖」ができ、分類器の精度が体験の上限になる、
  (3) そもそもArilsの価値の大半(呼吸・瞬き・視線・口パク・撫で)は
  「顔がどこか」+「体はその他全部」で成立し、姿勢の名前を必要としない。
- **代わりに錨(アンカー)を逆転する。**
  現在: シルエット→首のくびれ→頭→その中で目・口(立ち絵前提が先頭にある)。
  提案: **目ペアを全域で先に探し→顔→頭を目から逆算→体=残り全部**。
  姿勢は入力ではなく、顔と体の位置関係から**導出される連続特徴量**(`PoseTraits`)になる。
- **既存の調停パターンに乗せる。** 新しい顔優先推定器は `FaceLayoutEstimating` の
  1実装として追加し、既存の `CompositeFaceEstimator` が信頼度で従来経路と競わせる
  (被写体マスクの `IllustrationSubjectMaskArbiter` と同じ「両方計算して良い方」の流儀)。
  立ち絵では従来経路が勝ち、浮遊絵では顔優先が勝つ — 分類器なしの自然なルーティング。
- **手動補正UIが最後の数%を埋める。** どんなに賢くしても外れる絵は残る。
  自動が外れた時の体験を「失敗」から「10秒の手直し」に変えるのが
  「大抵のイラスト対応」の実質的な完成条件。

## 現状の立ち絵前提の棚卸し(直す場所の地図)

| 前提 | 場所 | 一般化の方向 |
|---|---|---|
| 頭=シルエット上部ローブ、首=幅のくびれ | `AnimeFaceEstimator` 手順1〜2 | 顔優先推定器では目から頭を逆算(くびれ不要) |
| 目・口は頭部高さの固定比率バンド内 | `AnimeFaceEstimator` 手順5〜6 | 顔優先経路ではバンド自体が目から導出される |
| 体の左右端の帯=後ろ髪、肩帯・腕帯の位置 | `BindingSynthesizer.makeRig` | マスク幾何(細長い突出部)から揺れ領域を検出 |
| 呼吸は体の底辺ピボットで持ち上げ | `BindingSynthesizer` body | 体塊の重心と接地情報からピボットを決定 |
| 首=頭矩形の下端で頭と体を切る | `PartPlanner`/`LayerFactory` | 顔スケールから首位置を推定(顎下×比率) |
| 縦長=全身と仮定した探索範囲調整 | `AnimeFaceEstimator` `isTallFullBody` | `PoseTraits` に吸収 |

## アーキテクチャ

### M1: 顔優先推定器(FaceFirst)

- 新型 `FaceFirstAnimeEstimator: FaceLayoutEstimating`。手順:
  1. 被写体マスク内**全域**(または上部75%)で、既存の目ペア探索
     (ぼかし密度ピーク+NMS+幾何スコアリング — チョーカー誤認対策で鍛えた機構)を実行
  2. 目の間隔 `eyeSep` から顔・頭を逆算: 頭幅≈`k1×eyeSep`、頭上端≈目から`k2×eyeSep`上、
     顎≈`k3×eyeSep`下(k1〜k3は古典的アニメ比率。既存テンプレ比率と整合させる)
  3. 口を目基準の期待位置で検証(既存の口検出をそのまま流用)。
     口が見つかる→信頼度加点。見つからない→減点(誤ペア対策)
  4. 信頼度は「ペアの幾何スコア×口検証×マスク内充足率」で構成し、
     `CompositeFaceEstimator` の調停に乗せる
- 従来の `AnimeFaceEstimator` は**無変更で共存**。立ち絵の実績を守る。
- 全域探索の誤ペア(服の装飾など)対策: ペア候補に「その下に口がある」制約を必須化。

### M2: PoseTraits と体バインディングの一般化

```swift
struct PoseTraits: Sendable {
    var headToSubjectRatio: Float        // 顔サイズ/被写体サイズ(全身⇄バストアップ)
    var bodyMassDirection: SIMD2<Float>  // 顔から見た体塊の方向(下=立ち、斜め=座り等)
    var feetGrounded: Bool               // マスク下端が接地しているか(浮遊判定)
    var flowingAppendages: [CGRect]      // マスクの細長い突出部(髪・リボン・羽衣・尻尾)
}
```

- `PartPlanner`/`BindingSynthesizer` が `PoseTraits` を受け取り:
  - **呼吸ピボット**: 接地なら従来通り底辺、浮遊なら体塊重心(ゆったり上下に変更)
  - **揺れ領域**: 立ち絵決め打ちの左右帯をやめ、`flowingAppendages` へ
    `SwayChannel` を割り当てる(細長い突出部の付け根→先端の rampDown)。
    浮遊絵の羽衣・リボンが姿勢を知らずに揺れる — 見栄えの主役
  - **重心移動レイヤー**: `feetGrounded == false` なら無効化し、代わりに緩い浮遊ドリフト
- 突出部検出は純ロジック(マスクの距離変換+細長比)でテスト可能に。

### M3: 顔レイアウトの手動補正(保険)

- `AutoRigPipeline` に `makeAvatar(from:layout:)`(検証済み `FaceLayout` を注入)を公開。
  Quality 側にも同型の注入口を用意。
- `ImageRiggingView` に「Arilsの検出結果を表示→目・口・頭矩形をドラッグ補正→再リギング」
  のオーバーレイを追加(既存 `PartSelectionOverlay` の流儀を流用)。
- 補正した `FaceLayout` は保存ペットに残し、再リギング時に再利用する。

### M4: 特徴量で吸収できないトポロジーだけ個別対応

- 横向きに寝ている: 目ペアの傾きが大きい場合、座標系ごと回して推定→戻す
- 後ろ姿・顔なし: 正直に「顔が見つからない」を警告し、
  揺れのみモード(呼吸+髪物理だけ)を**明示的な選択肢**として提示(黙って劣化しない —
  `QualityPairAssessment` と同じ「断定せず確認はホストに委ねる」流儀)
- 極端なチビキャラ: 顔比率が大きい場合の k1〜k3 の補正テーブル

### マスク品質(失敗の記録と再挑戦の条件)

2026-07-14 に「Visionと境界色フラッドの両方を計算し、被覆率で良い方を選ぶ調停器」を
実装したが、**即日リバートした**。水彩・浮遊絵(abc.png級)ではフラッドが正しく勝つ一方、
白髪×白背景の立ち絵(test2.png級)ではフラッドが髪の内部へ漏れ、その漏れ量が
被覆率ゲート(Vision比72%)をすり抜けて採用され、これまで動いていた画像が壊れた。

**教訓: 被覆率では「Visionの丸まり」と「フラッドの漏れ」を区別できない。**
面積はどちらの失敗でも少しずつ減るだけで、失敗の形が違う(丸まり=境界が滑らかに内側へ、
漏れ=内部にギザギザの穴と断片)。再挑戦するなら判定基準は面積ではなく**形状**:

1. **境界エッジ整合**: マスク境界画素のうち、画像の強い勾配上に乗っている割合。
   正しい輪郭は絵のエッジに沿う。漏れたフラッドの境界は髪の平坦部を横切る(整合率低)
2. **境界のギザギザ度**: 周長²/面積。漏れは周長が爆発する。Visionの団子は低い
3. **内部の穴の数**: 被写体内部に生じた背景の島の数。漏れの指紋
4. そもそも**選択ではなく融合**が本命: Vision を「どこが被写体か」の領域事前分布に、
   フラッド/エッジを境界の精細化に使う(ガイデッドフィルタ/マッティング帯)。
   これはM5のマッティングと同じ道具立てになる
5. 暫定の実用解: リギング画面に**切り抜き方式の3択**(自動/Vision/背景色)を出す。
   M3の手動補正と同じ「外れたら10秒で直せる」思想で、判定器の完成を待たずに済む

いずれの場合も、**test2.png級(白髪×白背景の立ち絵)と abc.png級(水彩・浮遊)の両方を
受け入れ基準に含める**こと。片方だけ見て入れ替えると今回の再発になる。

### M5(研究枠): ML補助

- アニメ特化の顔/ポーズ検出 CoreML モデルを `FaceLayoutEstimating` の差し替え実装として
  オプトイン追加(ヒューリスティック主経路+ML補助 — 顔検出・深度と同じ構図)。
  モデルは同梱せず任意ダウンロード。外部API送信はしない(ローカル優先原則)。
- 半透明衣装の真のアルファ(マッティング)もこの枠(現状は不透明として切り抜き)。

### 受け入れ基準

- **M1**: 浮遊ポーズ合成キャラ(顔が右上・髪塊が顔の下まで流れる)で目・口が実位置に載る。
  既存の立ち絵・斜め向き・チョーカー・帽子の回帰テストが全て無変更で通る。
  実画像スモーク: `abc.png` 級で目が顔に載る(手元確認。画像はコミットしない)。
- **M2**: 浮遊合成キャラで、突出部(リボン相当)に揺れチャンネルが割り当てられ、
  重心移動が無効化される。立ち絵の既存モーションは数値回帰なし。
- **M3**: 検出が外れた画像でも、矩形ドラッグ→再リギングで10秒以内に修復できる。
  補正値が保存ペットに永続化され、再起動後も維持される。
- **M4**: 顔が見つからない画像で例外ではなく警告+揺れのみモードの提案が返る。

## テスト方針

- 合成キャラ群を拡充: 浮遊(顔右上+髪カーテン)、座り、バストアップ、傾き顔、チビ。
  いずれも `SyntheticCharacter` の流儀(決定論・ヘッドレス)で。
- 顔優先とシルエット経路の**調停**そのものをテストする(どちらが勝つべきかを固定)。
- 実画像(`test2.png`/`abc.png` 等)はコミットせず、手元スモークの手順だけ記す:
  `makeAvatar` → 各パーツ矩形の出力を目視確認。

## 決めておくこと(実装開始時に確認)

1. 比率定数: 頭幅=k1×目間隔(仮: 3.1)、頭上端=k2(仮: 1.6)、顎=k3(仮: 1.5)。
   既存テンプレ(目幅0.22×頭幅等)と往復で矛盾しない値に校正する
2. 顔優先の信頼度スケール: 従来経路(首くびれあり≈0.3〜0.55×係数)とどう並べるか。
   立ち絵で従来経路が勝ち続けることを回帰テストで固定する
3. 全域目探索の計算量上限(現在はバンド内のみ。全域×ぼかしのコスト確認)
4. 突出部検出の閾値: 細長比・最小面積・付け根の定義
5. M3のUIスコープ: 目・口・頭の3矩形だけか、首線も含めるか(推奨: 首線も)
