# Arils 3D化ロードマップ(計画書)

正面+横向きの2枚から奥行きを推定し、キャラクターを段階的に3D化する計画。
2026-07-08 時点の構想を起点とし、2026-07-11 に Stage A(M1〜M4) を実装した。
(2026-07-09 レビュー反映: 透明×デプスの共存設計、旧アーカイブ互換の明確化、
「厚み制約」への表現修正、ArilsMotion 不変条件の緩和、Stage B の左右非対称を追記)

## 前提と結論(先に要点)

- **モーションシステム(ArilsMotion)の API・レイヤー構造・時間変化ロジックは維持する。** パラメータ語彙(`angleX`、`eyeLeftOpen`…)はレンダリング方式と独立に設計してあるため、3D化とは主に「リグとレンダラーの差し替え」であり、呼吸・視線・瞬き・くしゃみ・髪物理の仕組みはそのまま3Dでも動く。ただし**出力値の校正と3Dへのマッピングは調整対象**とする: `angleX/Y` の上限・応答曲線、髪揺れの2D水平変位→3D軸(頭部ヨー軸まわり等)への写像、撫で位置の3Dヒットテスト、くしゃみの頭回転軸(3Dではピッチ軸の実回転になる)、3D回転⇄横絵クロスフェード境界での連続性。
- **完全な3Dモデル復元(任意角度)は研究課題であり、段階的に攻める。** 体感価値の8割は「±20°程度の首振り・視差が本物の奥行きで動く」ことで得られる(2.5D+)。フル3Dハル化はその後。
- 2枚のイラストは通常**幾何学的に矛盾している**(アニメ絵の様式化)。「正確な復元」ではなく「破綻しない説得力」を目標にする。既存の `QualityPairAssessment`(同一キャラ判定)と首レジストレーションはこのための土台として流用する。

## 全体像: 3ステージ

```
Stage A: 深度マップ 2.5D+       Stage B: ビジュアルハル 3D        Stage C: ML/生成補助(研究枠)
  正面メッシュに Z を持たせ、      2枚のシルエット交差から           オンデバイス深度推定モデル、
  透視投影で本物の視差を出す       粗い3Dメッシュ+テクスチャ投影      生成的な背面/遮蔽補完
  (±20°の首振りが激変する)        (±60°程度まで回せる)             (将来、必要になったら)
```

## Stage A: 深度マップによる 2.5D+(本命・最初にやる)

**実装済み**: `DepthMap` / `ThicknessProfile` / `SilhouetteDepthEstimator`、v2深度リグ、`rotate3D`、`DeformationEvaluator3D`、Metal透視投影+カットアウト/フェザー2パス、`QualityHybridTurnModel` による横絵クロスフェードを提供する。Stage B/C は未実装。

### A-1. 奥行き推定 — 「横絵=高さごとの厚み制約」という考え方

ユーザー構想の核。ただし正確には、横向き画像が与えるのは **Zの実測値ではなく「高さごとの厚み制約(深度事前分布)」**である。横シルエットから取れるのは各高さ y での前端〜後端(min/max Z)であり、**正面画像の各画素がその厚みのどこに位置するかは横絵だけでは決まらない**。この前提で設計する:

1. **横絵のシルエット解析**: 各高さ y について、横シルエットの前端〜後端 = その高さの厚みレンジ。鼻先・額・後頭部・胸・背中の前後端カーブが取れる(既存の `SubjectMask` / 幅プロファイル解析を流用)。ただしこれは髪・顔・体の**合算シルエット**である点に注意。
2. **部位帯ごとの対応付け**: 首レジストレーション(`QualityViewRegistration`)で高さを対応させた上で、**部位分割単位**で厚みを適用する(頭部帯には頭部プロファイル、胴体帯には胴体プロファイル)。頭部内では**ランドマーク対応**を使う: 正面・横それぞれに既存の顔レイアウト推定(`FaceLayoutEstimating`)を適用し、「横絵の前端極値=鼻先」「目の高さ」「後端=後頭部」を正面の顔レイアウトへ対応付けて、行内Z分布のアンカーにする。
3. **行内の分布**: アンカー間は**シルエット膨張**(正面シルエットの距離変換を断面形状として Z に写像)で補間する。「輪郭で Z=浅、鼻・額アンカーで Z=深(横絵由来の厚み上限)」。
4. **シルエットだけでは解けないもの(制限として明記)**: 前髪と後頭部の層分離(→前髪は頭部より一定量手前の薄い層とする既定則)、腕が胴体の前か後ろか(→前と仮定する既定則+将来の手動指定)、横絵の遠い側に隠れた輪郭(→左右対称仮定)。これらは推定ではなく**明示的な既定則**として実装し、ドキュメントに書く。

横絵が無い場合(1枚のみ)もシルエット膨張+標準厚みプロファイルで動く**縮退経路**を必ず残す。

- 新規型: `DepthMap`(FloatPlane の Z版、部位ごと)、`DepthEstimating` protocol(全段差し替え可能の流儀を継続)
- 成果物の検証: 深度マップを画像として書き出すデバッグダンプ(今回のレイヤーダンプと同じ手法)+ 単調性・対称性の純ロジックテスト

### A-2. リグ拡張 — メッシュのZ化と「本物の回転」

- `DeformableMesh` に頂点Z(または部位ごとの `DepthMap` 参照)を追加し、フォーマットバージョンを v2 に上げる。
- `DeformationOp` に `.rotate3D(parameter:, axis:, pivot:)` を追加。**新規に v2 でリギングしたアバターのみ**、`BindingSynthesizer` が `angleX`/`angleY` に `perspectiveShift`(偽視差ワープ)ではなく実回転オペを割り当てる。ここが見た目の激変ポイント: 輪郭が正しく動き、鼻や前髪が頬に対して視差で動く。
- **後方互換は「オペはリグ文書に保存されたデータ」であることで担保する**。旧アーカイブには `perspectiveShift` オペがそのまま入っており、評価器は文書にあるオペを適用するだけなので、旧キャラクターは**従来の見た目のまま**表示される(Z=0 の板を実回転させることは起こらない)。旧アーカイブを3D化したい場合は**明示的な再リギング**(深度生成→v2として保存)のみ。挙動の全体切替は存在しない。
- 評価器は 3x3 行列 → 4x4(simd_float4x4)へ。既存の2D opは Z を素通しするだけなので共存できる。

### A-3. レンダラー拡張 — 透視投影+デプスバッファ(透明との共存設計)

- `MetalAvatarRenderer` を拡張: 頂点 (x,y,z)、透視投影(視野角は狭め〜9°程度、望遠でイラストの平面性を保つ)。シェーダは**アンリット(無照明)のまま**にする — アニメ絵にPBR照明は毒で、テクスチャの描き込みが照明そのもの。これは SceneKit/RealityKit を採らず自前 Metal を続ける最大の理由。
- **透明レイヤーとデプスの共存(設計判断)**: 現行レンダラーは背面→前面の合成(painter's algorithm)+premultiplied alpha で、羽根ぼかしエッジ・透明画素を多用している。素朴に depth write を有効化すると、透明な画素が奥のパーツを隠す・半透明の髪が欠ける。採用方式は**カットアウト+フェザーの2パス**:
  1. **不透明パス**: α ≥ 閾値(~0.5)の画素のみ描画(fragment `discard`)、depth test/write 両方有効。パーツ順不問で正しい自己遮蔽が得られる。
  2. **半透明エッジパス**: 全パーツを背面→前面(従来の zOrder 順)で再描画、depth test のみ有効・depth write 無効。羽根ぼかしの縁がここで乗る。
  - さらに従来の `zOrder` を**微小Zバイアス**として頂点Zに加算し、深度がほぼ同値のパーツ間(目・口 vs 顔)で旧来のレイヤー順を同点解決に使う。これにより旧アーカイブ(全頂点 Z=0)も2パス構成のまま従来と同じ見え方になる。
- 回転で生じる**引き伸ばし/裏面の露出**: ±20°に制限すれば、既存の拡散インペイント(頬・輪郭外側へのわずかな伸び)で吸収できる。輪郭のリム(縁1-2px)はアルファを立てて「紙の厚み」が見えないようにする。
- Quality の2枚クロスフェードとの関係: Stage A 完成後は「±20°は3D回転、それを超える `viewTurn` は横絵へクロスフェード」という**ハイブリッド**にする。自動振り向き(`QualityTurnModel`)はそのまま両方を駆動できる。

### Stage A の受け入れ基準

- マウスに追従した首振りで、鼻・前髪・輪郭が別々の速度で動く(視差)こと
- 全モーション(呼吸・瞬き・口同期・撫で・くしゃみ・髪)が無修正で動くこと
- 旧アーカイブがそのまま読めること、1枚のみでも(品質は落ちるが)動くこと

## Stage B: ビジュアルハルによる粗い3Dメッシュ(対応側 ±60°へ)

- **受け入れ角度は左右別に定義する**。Quality 版は片側の横画像しか持たないため、回転可能域は非対称になる:
  - **対応側**(横絵がある向き): 約 ±60° を目標。
  - **非対応側**: Stage A の小角度(±20°)まで。それ以上を望む場合は (a) 正面+左右横顔の**3枚入力**(完全版の条件)か、(b) **対称ミラーであることを明示した上で**の反対側合成、のどちらかをユーザーが選ぶ。黙ってミラーしない(Quality の「非対応側は反転しない」規則を継承)。
- **ビジュアルハル**: 正面シルエットをZ方向へ、横シルエットをX方向へ押し出し、その**交差**を取る(ボクセルグリッド 128³ 程度 → マーチングキューブ → デシメーション)。2枚の直交シルエットからの古典的な形状復元で、決定論的・オンデバイス・依存ゼロ。**ハルは凹形状を復元できない**: 鼻と頬の境界、前髪の隙間、腕と胴体の分離は原理的に不可。凹みが重要な部位(顔)は A-1 のランドマークアンカーで彫り込みを後付けし、前髪・腕は別レイヤー(カード群)として扱う。
- **テクスチャ投影**: 法線が正面向きのポリゴンへ正面画像、横向きへ横画像を投影し、境界は角度重みでブレンド。**背面は未知** — 対称ミラー+髪色の拡散インペイントで「後ろ姿らしきもの」を合成(ここが様式的にごまかせるかの勝負どころ)。
- **リグの3D移植**: 頭ボーン(首ピボットの3D回転)、髪は現行の `SwaySimulator` 出力を3Dの髪房ストリップに接続。目・口はメッシュ変形ではなく**表面上のUV空間デフォーム**として現行の仕組みを維持する(3Dで口を彫らない — Live2D系の口はテクスチャ操作の方が可愛い)。
- 課題(先に認めておく): 正面/横絵の様式矛盾は首・肩で段差になりやすい(レジストレーションのスケール補正+ハルの平滑化で吸収)。

## Stage C: ML/生成補助(研究枠・任意)

- `DepthEstimating` の差し替え実装として、CoreML 変換した単眼深度推定(Depth Anything 系)を**写真向け**に用意(アニメ絵には効きにくいので補助扱い。ここでもヒューリスティック主経路+ML補助という今回の顔検出と同じ構図)。
- 生成モデルによる背面・中間視点の補完(PAniC-3D 等のアニメキャラ3D復元研究の系譜)は、オンデバイス実行が現実的になった時点で再評価。**外部API送信はしない**(Pome のローカル優先原則)。

## 決めておきたいこと(実装開始時に確認)

1. **回転上限**: ±20°案(破綻ほぼゼロ)か ±30°案(視差は派手だが補完が目立つ)か
2. **1枚のみ画像の扱い**: 標準厚みプロファイルで3D化するか、従来の2.5D(perspectiveShift)に留めるか
3. **アーカイブ**: v2(Z入り)への自動アップグレード(再リギング)を保存時にやるか、明示ボタンにするか
4. **不透明カットアウトの α 閾値**: 0.5 を仮置き。髪の透け感が強い絵柄で閾値を下げるか、パーツ種別ごとに変えるかは M3 で実絵検証
5. **前髪・腕の前後既定則**(A-1 の「解けないもの」): 既定則のみで v2 を出すか、簡易な手動指定 UI を M4 に含めるか
